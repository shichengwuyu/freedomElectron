# 第 3 章 连线系统（SVG 贝塞尔 + 双层路径）

> 对应简历亮点 2：基于 SVG 贝塞尔曲线的连线系统，支持多种线型样式，双层路径设计（不可见命中层 + 可见描边层），提升交互精度与视觉表现。

## 3.1 连线数据模型

```ts
interface Edge {
  id: string                    // uuid
  source: { nodeId: string; portId: string }   // 起点必须端口方向 = out
  target: { nodeId: string; portId: string }   // 终点必须端口方向 = in
  style: EdgeStyle              // 用户可覆盖的样式
  createdAt: number
}

interface EdgeStyle {
  variant: 'solid' | 'dashed' | 'animated'   // 线型：实线/虚线/流动动画
  color?: string                // 默认按 target 端口 dataType 取色
  strokeWidth: number           // 默认 2，选中 3
}

// 渲染期派生状态（不持久化，由两端口的数据反推）
type EdgeRuntimeState = 'idle' | 'generating' | 'done' | 'error' | 'invalid-preview'
```

设计决策：**连线不存储路径几何**。路径每次渲染时从两端端口的实时坐标计算——因为节点位置随时在变，存储几何会造成状态同步地狱；SVG path 的 `d` 属性计算是纯函数，开销可忽略（见 3.7 的 memo 策略）。

## 3.2 贝塞尔路径计算

### 3.2.1 为什么是三次贝塞尔

二次贝塞尔（1 个控制点）曲线拐点生硬，无法让线在两端各自沿端口引出方向"顺滑伸出"；三次贝塞尔（2 个控制点）可以**起点控制点沿起点端口方向、终点控制点沿终点端口反向**摆放，天然形成"水平出、水平进"的缆线效果（节点编辑器的视觉惯例）。

### 3.2.2 控制点策略

```ts
// 端口的世界坐标与引出方向（in 端口方向取反）
// dir 取值如 right 端口 = {x:1,y:0}，bottom 端口 = {x:0,y:1}
function edgePath(s: PortAnchor, t: PortAnchor): string {
  const dx = t.point.x - s.point.x
  // 控制臂长：随水平距离自适应，限幅 [60, 400]
  // 太短 → 曲线像"折叠"；太长 → 密集连线互相缠绕
  const arm = clamp(Math.abs(dx) * 0.5, 60, 400)

  const c1 = { x: s.point.x + s.dir.x * arm, y: s.point.y + s.dir.y * arm }
  const c2 = { x: t.point.x - t.dir.x * arm, y: t.point.y - t.dir.y * arm }

  return `M ${s.point.x},${s.point.y} C ${c1.x},${c1.y} ${c2.x},${c2.y} ${t.point.x},${t.point.y}`
}
```

三个细节：

1. **反向连线**（终点在起点左侧，`dx < 0`）：`arm` 用 `|dx|` 计算后曲线会形成优雅的"S 形回环"，而不是折叠成一团——这正是控制臂长限幅下限 60 的作用；
2. **垂直堆叠**（两端口几乎同 x）：`arm` 退化为下限 60，曲线近似竖直的"S"，视觉可接受；
3. **端口方向多样**：`dir` 由端口位置（top/bottom/left/right）给出，上下出线的连线（如配置节点向下）同样成立，公式不感知具体方向。

### 3.2.3 拖拽中的临时连线

创建连线过程中渲染一条 `previewEdge`：起点固定为源端口，终点跟随鼠标（鼠标坐标转画布坐标），同一 `edgePath` 函数复用；目标端口合法时预览线吸附到端口、变绿色；非法时变红色虚线。**预览线复用生产线的路径函数**，保证"所见即所得"。

## 3.3 双层路径设计：交互精度的关键

```tsx
function EdgeLayer({ edge }: { edge: ResolvedEdge }) {
  const d = useMemo(() => edgePath(edge.source.anchor, edge.target.anchor),
                     [edge.source.anchor, edge.target.anchor])   // 路径 memo
  return (
    <g data-edge-id={edge.id}>
      {/* ① 命中层：透明、加粗、只响应 stroke 区域的指针事件 */}
      <path d={d} fill="none"
            stroke="transparent"          // 完全不可见
            strokeWidth={16}              // 有效命中宽度 16px
            pointerEvents="stroke"        // ★ 只有描边区域可点，填充不拦截
            onPointerDown={e => onEdgePointerDown(e, edge.id)} />
      {/* ② 描边层：可见视觉，pointer-events 全关（事件由命中层代理） */}
      <path d={d} fill="none"
            className={`edge edge-${edge.state}`}
            pointerEvents="none" />
    </g>
  )
}
```

**为什么必须有命中层**：可见描边只有 2px，而贝塞尔中段往往接近平缓，用户想点中一条线，鼠标要精确落在 2px 内——密集画布上几乎必然点到旁边的线或空白。16px 的透明命中层把容错半径放大 8 倍。

**为什么不用 `isPointInStroke` 手动命中**：那是 canvas 2D API，SVG 没有等价能力，需要手动做鼠标位置到曲线的数学求交（贝塞尔曲线求交要解四次方程或离散采样），复杂且慢。**透明粗 stroke + `pointerEvents="stroke"` 让浏览器原生完成命中测试**，零代码维护命中逻辑。

两个易错点：

1. `pointerEvents` 必须是 `"stroke"` 而不是 `"visibleStroke"`——后者在 stroke 为 `transparent` 时判定为不可见、不响应事件；
2. 命中层在下、描边层在上（`<g>` 内顺序），且描边层 `pointerEvents="none"`，否则 2px 可见线会"抢走"本该由命中层处理的事件，产生边缘点击不一致。

## 3.4 线型样式系统：让连线携带语义

| variant | 实现 | 语义 |
|---|---|---|
| solid（实线） | 默认 stroke | 已完成的静态依赖 |
| dashed（虚线） | `strokeDasharray: '6 8'` | 未激活/手动禁用的依赖 |
| animated（流动） | dasharray + `strokeDashoffset` 动画 | 数据正在生成，流向可视化 |
| error（红） | stroke 红 + 闪烁 | 生成失败 |
| selected | 加粗 3px + 外发光 filter | 选中态 |

```css
/* 流动动画：dashoffset 持续减小 → 虚线段向 target 方向"爬行" */
.edge-animated {
  stroke-dasharray: 6 8;
  animation: edge-flow 0.6s linear infinite;
}
@keyframes edge-flow { to { stroke-dashoffset: -14; } }  /* 6+8=14 一个周期 */
```

状态→样式映射是纯函数：`state = deriveEdgeState(edge, sourceNode, targetNode)`——源节点在 generating 则连线 animated，done 则 solid。**用户不点开节点，光看线就知道哪些链路在跑**。

配色按 target 端口 `dataType` 区分（image=紫、text=蓝、video=橙、audio=绿），密集画布中凭颜色即可预判连线接的是什么类型。

## 3.5 连线交互全流程

```
[创建]
端口 pointerdown → 记录源端口，进入 preview 模式（预览线跟随鼠标）
  → 移动经过候选端口：canConnect 校验（2.3 的规则矩阵 + 环检测）
      合法 → 吸附高亮绿色；非法 → 红色
  → pointerup 落在合法端口 → 写入 store（新增 edge）→ 命中层/描边层重建
  → pointerup 落在空白 → 弹出"快速创建菜单"（新建一个匹配 dataType 的节点并自动连上）
      ★ 这是节点编辑器的效率杀器：拖一下就"连线+建节点"一步完成

[重连]
按住连线端点（端点渲染为小圆柄）拖出 → 原 edge 进入 detach 预览态
  → 落到新端口：canConnect 通过 → 更新 edge.target；失败 → 弹回原位（不丢线）

[删除]
选中 + Delete/Backspace；或 hover 命中层出现 × 按钮
  → 删除前若该 edge 正在被生成任务引用 → 弹确认

[清理]
节点删除 → 级联删除其所有出入边（store 的 deleteNodes 内做，保证不变量：
  "任何 edge 的两端节点必然存在"）
```

快速创建菜单的实现：`pointerup` 在空白处时，用源端口 `dataType` 反查"能消费该类型的节点类型列表"（如 image → [image, panorama, video]），弹出跟随鼠标的菜单，选中后**在鼠标画布坐标处建节点 + 建 edge 一次 commit**（作为一个撤销单元）。

## 3.6 环检测：保证画布始终是 DAG

数据流依赖不允许环（环 = 死循环生成）。新连线 `(u → v)` 建立前，沿 v 的下游做图遍历：

```ts
function createsCycle(nodes: Record<string, AppNode>,
                      edges: Record<string, Edge>,
                      from: string, to: string): boolean {
  // 从目标节点出发沿下游走，如果回到源节点则成环
  const visited = new Set<string>()          // 防止菱形结构重复遍历
  const stack = [to]
  while (stack.length) {
    const cur = stack.pop()!
    if (cur === from) return true            // ★ 下游撞见源头 → 成环
    if (visited.has(cur)) continue
    visited.add(cur)
    // 收集 cur 的所有出边终点（按 target nodeId）
    for (const e of Object.values(edges)) {
      if (e.source.nodeId === cur) stack.push(e.target.nodeId)
    }
  }
  return false
}
```

复杂度 O(V+E)，画布规模（几百节点）下微秒级，拖拽预览时实时调用无感知。DFS 栈实现而非递归——避免超深链路（如 100 节点串联）栈溢出。

## 3.7 性能：几百条连线的渲染

1. **路径 memo**：`d` 只依赖两端锚点坐标（`useMemo` 按引用比较），节点不动则路径字符串引用不变，React 跳过 DOM 更新；
2. **锚点引用稳定**：端口世界坐标按 `node.position + port offset` 缓存在节点渲染层，拖拽中只有被拖节点相关的边重算；
3. **视口裁剪**：连线包围盒（两端点 + 控制点外包）与视口求交，屏外边不渲染 SVG 节点；
4. **拖拽期间的降级**：拖动节点时其关联边理论上每帧重算 `d`——实测几百条边内 SVG 更新可跑满 60fps，无需降级；若上千条，可拖拽中切换为"直线近似"（`M x1,y1 L x2,y2`），落定后恢复贝塞尔；
5. **SVG 渲染顺序**：edge 层整体在 node 层之下（分组节点更底），保证节点永远压住线，命中测试也不会被线拦截节点点击。

## 3.8 面试考点提炼

1. **"双层路径是干嘛的？"** → 3.3：命中层 16px 透明 + `pointerEvents="stroke"`，把 2px 可见线的点击容错放大 8 倍；能说出 `visibleStroke` 对 transparent 不生效这个坑 = 实战过；
2. **"控制点怎么定的？"** → 3.2：沿端口引出方向、臂长 = 水平距离一半且限幅 [60,400]；被问"反向连线呢"能答 S 形回环；
3. **"怎么防止环？"** → 3.6：新边建立前从 target 沿下游 DFS 撞 source 即拒绝，O(V+E)；
4. **"连线渲染怎么优化？"** → 路径纯函数 + memo + 视口裁剪 + 拖拽降级直线；
5. **"为什么不用现成库（React Flow）？"** → 如实答：评估过，但需要深度定制（dataType 规则矩阵、Agent 工具直接操作拓扑、流动语义样式），自研的路径/命中核心只占 ~800 行，可控性收益大于成本；同时承认 React Flow 的视口虚拟化思路有借鉴——**既证明调研过，又证明决策有依据**。
