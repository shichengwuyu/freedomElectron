# 第 2 章 节点系统（8 种节点类型）

> 对应简历亮点 1：支持 8 种节点类型（图片/全景/文本/配置/视频/音频/导演台/分组），每种节点具备独立渲染器、拖拽、缩放及连接端口功能。

## 2.1 领域模型：判别联合是整个系统的地基

画布上的一切功能差异（8 种节点长得不一样、行为不一样、数据不一样），在类型层面全部收敛为一个**判别联合（Discriminated Union）**：

```ts
// ---------- 基础几何与实体 ----------
interface Point { x: number; y: number }              // 画布坐标系下的点
interface Size { width: number; height: number }      // 节点尺寸

// 所有节点的公共骨架：type 是判别字段
interface BaseNode<T extends NodeType, D extends object> {
  id: string                 // 全局唯一（uuid v4），节点/连线/任务都靠它关联
  type: T                    // ★ 判别字段：switch(node.type) 后 TS 自动收窄
  position: Point            // 画布坐标（不是屏幕坐标！见 2.4）
  size: Size
  data: D                    // 各类型私有的业务数据（泛型注入）
  parentId?: string          // 分组归属：group 节点的 id（分组移动时级联）
  zIndex: number             // 层叠顺序，选中即置顶
  locked: boolean            // 锁定后不可拖拽/删除
  createdAt: number
  updatedAt: number
}

// ---------- 8 种节点的私有数据 ----------

// 图片节点：围绕"一次生成任务"的状态机
interface ImageNodeData {
  status: 'idle' | 'queued' | 'generating' | 'done' | 'error'
  prompt: string                       // 正向提示词
  negativePrompt?: string              // 反向提示词
  model: string                        // 模型标识（如 comfy:sd-xl / api:xxx）
  aspectRatio: '1:1' | '16:9' | '9:16' // 输出比例
  refAssetIds: string[]                // 参考图（角色/场景卡，用于一致性）
  outputUrl?: string                   // 生成结果（Supabase Storage URL）
  progress?: number                    // 0~1，generating 时驱动进度条
  error?: string                       // 失败原因（error 态展示）
}

// 视频节点：首帧图 + 提示词 → 视频片段
interface VideoNodeData {
  status: 'idle' | 'queued' | 'generating' | 'done' | 'error'
  firstFrameAssetId?: string           // 首帧（通常连线自图片节点）
  prompt: string                       // 镜头运动/动作描述
  durationSec: number                  // 目标时长（生视频服务有上限，如 10s）
  outputUrl?: string
  error?: string
}

// 全景节点：360° 环境图，供导演台做场景背景
interface PanoramaNodeData {
  status: 'idle' | 'generating' | 'done' | 'error'
  prompt: string
  outputUrl?: string                   // equirectangular 全景图
  sceneId?: string                     // 关联到导演台里的场景实例
}

// 文本节点：承载剧本/分镜/台词等中间文本产物
interface TextNodeData {
  kind: 'novel' | 'script' | 'storyboard' | 'subtitle' | 'free'
  content: string
  // 分镜类文本额外携带结构化镜头列表（供一键展开为图片节点）
  shots?: Array<{
    index: number
    description: string    // 画面描述 → 默认填入图片节点 prompt
    lines: string[]        // 台词 → 字幕轨
    durationSec: number
  }>
}

// 配置节点：全局参数（不连线，作用于下游同类任务）
interface ConfigNodeData {
  scope: 'image' | 'video' | 'audio'
  values: Record<string, string | number>  // 如默认模型、默认比例、种子
}

// 音频节点：TTS 配音 / BGM
interface AudioNodeData {
  status: 'idle' | 'generating' | 'done' | 'error'
  source: 'tts' | 'upload'
  text?: string                        // tts 源文本
  voiceId?: string                     // 音色
  outputUrl?: string
  durationSec?: number                 // 合成时要对齐时间轴
}

// 导演台节点：3D 场景在 2D 画布上的"窗口"（详见第 5 章）
interface DirectorNodeData {
  sceneAssetIds: string[]              // 场景引用（全景/角色）
  cameraState?: unknown                // 最近一次机位快照（由 3D 应用回传）
  status: 'loading' | 'ready' | 'error'
}

// 分组节点：视觉容器，框住子节点，可整体拖拽/改色/命名
interface GroupNodeData {
  title: string
  color: string
  collapsed: boolean                   // 折叠时子节点隐藏
}

// ---------- 收敛 ----------
type NodeType = 'image' | 'panorama' | 'text' | 'config'
              | 'video' | 'audio' | 'director' | 'group'

type AppNode =
  | BaseNode<'image', ImageNodeData>
  | BaseNode<'video', VideoNodeData>
  | BaseNode<'panorama', PanoramaNodeData>
  | BaseNode<'text', TextNodeData>
  | BaseNode<'config', ConfigNodeData>
  | BaseNode<'audio', AudioNodeData>
  | BaseNode<'director', DirectorNodeData>
  | BaseNode<'group', GroupNodeData>
```

**为什么是判别联合而不是类继承**：节点要 JSON 序列化进 IndexedDB 和 PostgreSQL，类实例化的反序列化很痛苦；判别联合是纯数据 + 纯函数的模型，`switch (node.type)` 分支内 TS 把 `node.data` 收窄成对应类型，**编译期穷举检查**保证新增节点类型时漏处理的分支直接报错。

## 2.2 渲染器注册表：开闭原则的实现

```ts
// 渲染器统一契约：拿到节点 + 画布能力句柄
interface NodeRendererProps {
  node: AppNode
  selected: boolean
  // 由画布核心注入的交互能力，渲染器只管"长什么样"
  onStartDrag: (e: React.PointerEvent) => void
  onStartConnect: (portId: string, e: React.PointerEvent) => void
  updateData: (patch: Partial<unknown>) => void   // 类型化包装 store 更新
}

// 注册表：新增节点类型 = 写一个组件 + 加一行注册，画布核心零改动
const rendererRegistry: Record<NodeType, React.FC<NodeRendererProps>> = {
  image: ImageNodeRenderer,
  panorama: PanoramaNodeRenderer,
  text: TextNodeRenderer,
  config: ConfigNodeRenderer,
  video: VideoNodeRenderer,
  audio: AudioNodeRenderer,
  director: DirectorNodeRenderer,
  group: GroupNodeRenderer,
}

// 节点宿主：统一处理公共外观（选中框、端口、错误角标），再分发渲染器
function NodeHost({ id }: { id: string }) {
  // ★ 细粒度订阅：只有本节点数据变化才重渲染（见 2.8）
  const node = useCanvasStore(s => s.nodes[id])
  const selected = useCanvasStore(s => s.selection.includes(id))
  const Renderer = rendererRegistry[node.type]
  return (
    <div className="node-host" data-node-id={id} style={hostStyle(node)}>
      {node.type !== 'group' && <Ports ports={getPorts(node)} />}
      <Renderer node={node} selected={selected} {...useNodeActions(id)} />
      {selected && <SelectionFrame size={node.size} />}
    </div>
  )
}
```

公共/私有职责划分：**端口、选中框、zIndex、坐标 = 宿主统一管；内容、状态徽标、配置面板 = 各渲染器自己管**。这样 8 个渲染器里不会出现 8 份重复的选中逻辑。

## 2.3 端口系统：连接规则矩阵

```ts
type PortDirection = 'in' | 'out'
type DataType = 'image' | 'video' | 'audio' | 'text' | 'config' | 'scene'

interface PortDef {
  id: string
  direction: PortDirection
  dataType: DataType
  label: string
  allowMultiple: boolean   // 输入端口是否允许多条入线（false = 新连线顶掉旧线）
  position: 'top' | 'bottom' | 'left' | 'right' | 'auto'
}
```

每种节点在类型定义时声明端口模板，图片节点典型配置：

| 端口 | 方向 | dataType | allowMultiple | 语义 |
|---|---|---|---|---|
| 参考图 ×N | in | image | true | 角色/场景卡作为一致性参考 |
| 文本提示 | in | text | false | 分镜描述注入 prompt |

**连接规则矩阵**（`canConnect(from: PortDef, to: PortDef): ConnectError | null`）：

1. 方向校验：`out → in`，同向不可连；
2. 自连校验：不允许连接自身节点；
3. 类型校验：`dataType` 相同，或在白名单转换表内（`text → config` 允许，用于 prompt 覆盖）；
4. 容量校验：目标输入端口已满且 `allowMultiple=false` 时提示"将替换现有连线"；
5. 环校验：见 3.6 的 DFS 算法。

矩阵是一个纯函数，**画布交互、Agent 的连线工具、后端导入校验三处复用同一份实现**——保证人和 AI 建立的连线遵守同样规则。

## 2.4 坐标系与视口：一切交互的地基

画布有两个坐标系：

- **屏幕坐标系**：鼠标事件的 `clientX/clientY`，原点在视口左上角，单位 px；
- **画布坐标系**：节点存储的 `position`，原点任意（可负），单位是"画布单位"。

视口模型（唯一真源，存 `uiStore`）：

```ts
interface Viewport {
  x: number      // 平移
  y: number
  scale: number  // 缩放 0.1 ~ 4
}

// 屏幕点 → 画布点：先减平移，再除缩放
function screenToCanvas(v: Viewport, sx: number, sy: number): Point {
  return { x: (sx - v.x) / v.scale, y: (sy - v.y) / v.scale }
}
// 画布点 → 屏幕点：先乘缩放，再加平移（渲染节点/连线用）
function canvasToScreen(v: Viewport, p: Point): Point {
  return { x: p.x * v.scale + v.x, y: p.y * v.scale + v.y }
}
```

DOM 实现上，画布内容容器用单一 CSS transform：`transform: translate(${v.x}px, ${v.y}px) scale(${v.scale})`，浏览器对合成层 transform 走 GPU，性能远优于逐节点改 left/top。

**最容易翻车的细节**：所有鼠标交互拿到的都是屏幕坐标，必须先转换成画布坐标再参与逻辑；反之节点渲染坐标经容器 transform 自动映射，不要二次手工换算（否则缩放后拖拽会漂移——这是节点编辑器最经典的 bug）。

## 2.5 缩放：锚点缩放的公式推导

滚轮缩放要求**鼠标指向的内容点缩放前后保持在屏幕同一位置**（否则感觉内容乱跳）。

设鼠标屏幕位置 `m`，当前视口 `{x, y, k}`，新缩放 `k'`：

1. 鼠标下的画布点：`p = (m - t) / k`（缩放前）
2. 缩放后要求：`m = p * k' + t'`
3. 解出新平移：**`t' = m - (m - t) * (k' / k)`**

```ts
function zoomAt(v: Viewport, mx: number, my: number, factor: number): Viewport {
  const k = clamp(v.scale * factor, MIN_SCALE, MAX_SCALE) // 限制 0.1~4
  const ratio = k / v.scale
  return { scale: k, x: mx - (mx - v.x) * ratio, y: my - (my - v.y) * ratio }
}

// wheel 监听：passive:false 才能 preventDefault 阻止页面滚动
canvasEl.addEventListener('wheel', e => {
  e.preventDefault()
  const factor = Math.pow(SCROLL_SPEED, -e.deltaY)   // deltaY 正负决定放大缩小
  setViewport(zoomAt(viewport, e.clientX, e.clientY, factor))
}, { passive: false })
```

另外实现 Ctrl+滚轮 = 步进缩放（吸附 0.25/0.5/1/2 等档位）、双击空白 = 复位 100%、缩放跟随 = 空格拖拽平移（临时切换鼠标语义）。

## 2.6 拖拽：绕过 React 的高频更新

拖拽每秒产生上百次 pointermove，如果每次都 `setState`，几百个节点的 React调和会把帧率拖垮。方案是**两阶段提交**：

```ts
function startNodeDrag(e: React.PointerEvent, hitId: string) {
  const store = useCanvasStore.getState()
  // ① 快照阶段：记录起始视口与所有被选中节点的初始位置
  const start = { sx: e.clientX, sy: e.clientY, viewport: ui.viewport }
  const targets = store.selection.includes(hitId)
    ? store.selection : [hitId]                 // 点中未选中节点 = 单选拖拽
  const origin = Object.fromEntries(
    targets.map(id => [id, store.nodes[id].position]))

  const el = e.currentTarget as HTMLElement
  el.setPointerCapture(e.pointerId)             // 捕获指针：移出节点也持续收到 move

  const onMove = (ev: PointerEvent) => {
    // ② 屏幕位移 → 画布位移（除以缩放！）
    const dx = (ev.clientX - start.sx) / start.viewport.scale
    const dy = (ev.clientY - start.sy) / start.viewport.scale
    // ③ 吸附计算：候选对齐线 = 其他节点四边/中心线
    const snap = computeSnap(targets, origin, dx, dy, SNAP_THRESHOLD /* 6px */)
    // ★ 高频路径不走 React：直接改 DOM transform
    for (const id of targets) {
      nodeEls[id].style.transform =
        `translate(${origin[id].x + snap.dx}px, ${origin[id].y + snap.dy}px)`
    }
    renderAlignGuides(snap.guides)              // 参考线层同步
  }
  const onUp = (ev: PointerEvent) => {
    el.releasePointerCapture(e.pointerId)
    // ④ 提交阶段：pointerup 才写入 Zustand（触发持久化/撤销栈/UI 重渲染）
    commitPositions(targets, origin, ev)        // 内部含 alignGuides 清理
    el.removeEventListener('pointermove', onMove)
  }
  el.addEventListener('pointermove', onMove)
  el.addEventListener('pointerup', onUp, { once: true })
}
```

要点清单：

1. **`setPointerCapture`**：拖拽中鼠标飞出节点仍能收到事件，不需要全窗口监听；
2. **吸附**：把 `dx` 候选值与所有未选中节点的边线/中心线求差，差值 < 6px 则吸附并生成参考线；参考线渲染在独立 SVG 图层，避免触发节点重渲染；
3. **分组级联**：拖 group 节点时 targets 扩展为全部子节点（`parentId` 反查），子节点相对位置不变；
4. **框选**：空白处按下进入 rubber-band，实时计算与节点包围盒相交的节点集合，松手写入 `selection`；Shift 加选、在选中集合内按下 = 移动整体。

## 2.7 各节点类型的差异化设计速览

| 节点 | 核心职责 | 关键实现点 |
|---|---|---|
| 图片 | 生成任务的载体 | 状态机 idle→queued→generating→done/error 驱动 UI；缩略图懒加载 + Storage CDN 裁剪参数 |
| 视频 | 片段生成 | 首帧输入端口强制连线（校验层拦截）；结果 video 元素 hover 预览 |
| 全景 | 3D 场景背景 | 生成后可"发送到导演台"，建立 sceneId 关联 |
| 文本 | 剧本/分镜容器 | 自动高度（内容撑开）；分镜 shots 支持一键展开成 N 个图片节点 |
| 配置 | 下游默认参数 | 不参与连线拓扑，作用域按 scope 匹配下游节点 |
| 音频 | 配音/BGM | 生成后展示波形（WebAudio 解码）；durationSec 供合成对齐 |
| 导演台 | 3D 窗口 | 内嵌 iframe，双击放大为全屏层（见第 5 章） |
| 分组 | 组织结构 | 视觉在最底层（zIndex 最低）；子节点集合随移动/删除级联 |

## 2.8 渲染性能：从 O(n) 重渲染到 O(变更数)

1. **实体化存储**：`nodes: Record<string, AppNode>` 而不是数组——按 id 订阅和更新都是 O(1)，数组要遍历找 index；
2. **selector 细粒度**：`useCanvasStore(s => s.nodes[id])`，单个节点数据变化只重渲染它自己；
3. **组件 memo**：`NodeHost` 用 `React.memo` + 自定义比较（id + updatedAt）；
4. **视口裁剪（虚拟化）**：渲染前用视口矩形与节点包围盒求交，屏幕外节点跳过渲染（保留数据）；几百节点全量渲染 DOM 数会破万，裁剪后常驻 DOM 通常 < 200；
5. **大图占位**：done 状态的图片节点用 `content-visibility: auto` + 固定宽高比容器，避免图片解码阻塞；
6. **transform 合成层**：节点定位全走 transform，避免 layout/paint，只有内容变化才 paint。

## 2.9 面试考点提炼

1. **"8 种节点怎么设计的？"** → 判别联合 + 渲染器注册表（2.1/2.2），关键词：开闭原则、编译期穷举检查；
2. **"拖拽怎么做的、怎么优化？"** → 两阶段提交 + setPointerCapture + 绕过 React 直接改 DOM（2.6），这是最容易被追问的题；
3. **"缩放怎么保证不飘？"** → 锚点缩放公式推导（2.5），能现场推导加分；
4. **"几百个节点卡不卡？"** → 2.8 的六连招，重点是"视口裁剪 + selector 细粒度订阅"两条；
5. **埋的坑题**："拖拽时鼠标移出节点为什么还收得到事件？" → Pointer Capture；
6. **坐标系混淆**是这类项目的头号 bug 来源，主动讲 2.4 的"两次换算"原则能体现实战经验。
